Most of the text I read in a day is code, and most of the code I read is set badly. Not ugly, exactly — just thoughtless. Lines run to the edge of a forty-inch monitor, code sits on pure white, and the only hierarchy is the syntax highlighter's opinion.

Typography is not decoration. It is the set of decisions that let a reader forget they are reading. Code deserves the same courtesy as prose.

## Measure before you choose a font

A comfortable line is somewhere between sixty and eighty characters. That is true for an essay and true for a function. If a line of code requires a head turn, the eye loses its place; if the code is dense, the loss is expensive.

The fix is not a smaller font. Set the measure, then let the editor wrap or the reader scroll.

## Leading is the quiet variable

Monospace text at default line height looks like a wall. Add a little air — 1.7 to 1.9 for prose, 1.6 for code — and the same paragraphs become invisible in the best way. You notice the content, not the type.

> Typography exists to honor content.
>
> <cite>Robert Bringhurst</cite>

## Four habits worth keeping

- Set body text between fifteen and eighteen pixels, not twelve.
- Keep syntax colors low-saturation; neon is for terminals at 2 a.m., not for reading.
- Use one accent color, and use it for meaning rather than decoration.
- Give empty space a job. Margins are not wasted space; they are the pause before the next sentence.

## Paper is a good teacher

The reason this journal looks the way it does is simple: I set it like a book, then took away the paper. A page has margins, a running head, a folio, and a limit. Screens removed every one of those constraints, and we have been quietly paying for it ever since.

Put a few of them back. Your reader — usually you — will notice, even if only as a feeling that the words are easier to hold.
